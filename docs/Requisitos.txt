
Objetivo:

Evolucionar el sistema de Q&A (desarrollado en el Módulo 1) hacia un agente conversacional robusto. Los estudiantes deberán integrar memoria para gestionar diálogos coherentes y ampliar las capacidades del asistente mediante la creación de "herramientas" especializadas, permitiéndole decidir entre consultar la base de conocimiento documental (RAG) o acceder a información estructurada para responder con mayor precisión.

Descripción de la Actividad:

Partiendo del código y la base de conocimiento vectorial del Módulo 1, cada grupo mejorará su aplicación para que no solo responda preguntas aisladas, sino que pueda mantener una conversación contextual y utilizar diferentes fuentes de información según la naturaleza de la consulta del usuario.

Instrucciones Detalladas:

1. Punto de Partida: El Proyecto del Módulo 1

Cada grupo continuará trabajando sobre su propio repositorio de GitHub del módulo anterior. El primer paso es asegurarse de que el sistema RAG base sea funcional.

2. Implementación de Memoria Conversacional:

Objetivo: Dotar al asistente de la capacidad de recordar interacciones previas en una misma sesión para poder contestar preguntas de seguimiento (ej: "Háblame de sus servicios" y luego "¿Y cuánto cuesta el primero que mencionaste?").

Implementación: Utilizando su framework de LLM (LangChain, LlamaIndex, etc.), deberán integrar un gestor de memoria (ej. ConversationBufferMemory). El historial de la conversación deberá ser incluido en el contexto que se envía al LLM en cada turno.

Actualización de la Interfaz: La interfaz de Streamlit/Gradio debe ser modificada para mostrar el historial del chat de forma clara, simulando una ventana de mensajería.

3. Creación de una Herramienta de Datos Estructurados (Structured Tool):

Análisis: Los estudiantes deben identificar entre 5 y 10 preguntas frecuentes que se responden mejor con datos concretos y no con párrafos de texto (ej: "¿Cuál es el número de teléfono de servicio al cliente?", "¿Cuáles son los horarios de atención?", "Listar las sedes en Cali", "¿Cuál es el NIT de la empresa?").

Creación del "Tool":

Crearán un archivo simple (ej. un JSON o CSV) para almacenar esta información estructurada.

Implementarán una función en Python (una "herramienta") que pueda buscar y recuperar datos de este archivo de forma precisa. Por ejemplo, get_contact_info(query).

Esta herramienta NO debe usar la base de datos vectorial. Es un camino de recuperación de información diferente y determinista.

4. Implementación de un Enrutador de Peticiones (Router / Agent):

Concepto: Este es el núcleo de la actividad. El LLM ya no solo responderá preguntas, sino que primero deberá tomar una decisión: ¿qué herramienta debo usar para esta consulta?

Implementación: Usando las capacidades de "Agentes" (Agents) del framework, configurarán el sistema para que, ante una nueva pregunta del usuario, el LLM elija entre:

Herramienta 1: El sistema RAG (del Módulo 1) para preguntas abiertas sobre la empresa, su historia, sus productos, etc.

Herramienta 2: La nueva herramienta de datos estructurados para preguntas específicas sobre datos de contacto, horarios, etc.

Prompt Engineering para el Agente: Deberán diseñar un "meta-prompt" o prompt de sistema que instruya al agente sobre qué herramientas tiene disponibles y cuándo debería usar cada una.

5. Pruebas y Validación del Agente:

Diseñarán un conjunto de pruebas que demuestren que el agente funciona correctamente:

Prueba de RAG: Una pregunta general que deba ser respondida desde los documentos.

Prueba de Memoria: Una pregunta de seguimiento que dependa de la respuesta anterior.

Prueba de Herramienta Estructurada: Una pregunta directa como "¿Cuál es el horario?".

Prueba de Enrutamiento: Una conversación que combine los diferentes tipos de preguntas para ver si el agente elige la herramienta correcta en cada paso.

6. Documentación y Presentación:

Informe: Actualizarán su informe, añadiendo nuevas secciones o modificando las existentes para reflejar la nueva arquitectura:

Arquitectura del Agente: Un diagrama y explicación del nuevo flujo (Usuario -> Router -> Herramienta seleccionada -> LLM -> Respuesta).

Diseño de Herramientas: Explicación de las herramientas creadas y su justificación.

Gestión de Memoria: Detallar cómo se implementó y cuáles son sus beneficios y limitaciones.

Resultados: Mostrar ejemplos claros de las pruebas realizadas, incluyendo los "pensamientos" del agente (si el framework lo permite) para ver qué herramienta decidió usar y por qué.

Presentación: La sustentación será en vivo, con una demostración interactiva que ponga a prueba todas las nuevas capacidades del agente conversacional.
